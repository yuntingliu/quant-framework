This release combines dongfang's SDK workstation with dev_liu's research-evidence modules in one data, factor, strategy, validation, and reporting workflow. It also fixes gaps in RQ synchronization acceptance. The Python package, API, frontend, and lockfile use version `0.6.0`.

## Delivered capabilities

- Retains SDK v1 `strategy.py`, `factors/*.py`, `recipe.py`, `validation.py`, immutable source versions, and historical backtests.
- Adds Rank IC, ICIR, Newey-West t statistics, bootstrap intervals, 1/3/6-period decay, quantile returns, and chronological holdout diagnostics.
- Adds factor neutralization and equal-weight, minimum-variance, risk-parity, HRP, and explicit-expected-return maximum-Sharpe portfolio methods.
- Combines project quality gates, tail risk, concentration, execution fidelity, and frozen research evidence in Validation, with cost-sensitivity diagnostics in robustness analysis.
- Exposes `factor.research` and `backtest.validation` through the existing Agent Project-Files / Project-Run interfaces, preserving bounded research outputs.

## Fixes

1. Legacy RQ completion checks now include requested symbols, dates, and factor fields. A missing ROE column or partial symbol coverage cannot be marked complete.
2. Incremental start dates use each symbol's history and listing date. Another symbol's latest date cannot advance the start; late-starting history triggers backfill.
3. Daily coverage uses locally observable sessions and listing intervals to construct a symbol-date grid. Internal gaps fail acceptance; only explicit suspension state explains missing prices. Bars are rechecked after market-state synchronization.
4. Quantile membership is fixed on the signal date. Missing future prices affect computable returns but do not promote other stocks into higher groups. Returns stay unavailable when the entire group lacks exit prices.
5. Missing input-timing audits are reported as unverified rather than passed.
6. Validation uses copies of `context.diagnostics` and consolidates duplicate research-quality definitions and validators.
7. Validation source and frozen results remain accessible when current runtime data is missing; new backtests still check data. Project-switch isolation, dark parameter inputs, and icons under a URL subpath are fixed.
8. The facade check explicitly imports the current workspace so a different editable install cannot hide missing interfaces.

## Quality interpretation

`passed` / `status` reflect the project's chosen quality gates. `evidence_status` is a signal-evidence diagnostic with `pass`, `fail`, or `insufficient`. Existing requirements for fills and data reliability remain the default; signal evidence explains the result. Set `require_signal_evidence=True` in `validation.py` to make insufficient or failing evidence a quality failure. Passing does not guarantee returns.

Existing custom validation source is retained. Explicitly migrate the official template in Validation to adopt the new defaults; migration creates a version, and historical runs keep their original code and outputs.

## Usage for this release

Run from the release root in an environment with Python dependencies installed. The distributed archive included the frontend build:

```powershell
python -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8216
```

Open `http://127.0.0.1:8216/app/`. Follow the README to install missing dependencies. Source checkouts also require `npm --prefix apps/desktop ci` and `npm --prefix apps/desktop run build`.

Configure RQ in an untracked `.env` for real research; choose the scope, review the plan, synchronize, and verify coverage in Data. The release archive used existing sample fixtures, excluding test database mutations, personal credentials, and complete local caches. These samples are not an unbiased whole-market universe.

## Known limitations

- The session grid comes from existing local bars and market state. Detecting a date absent from every local table still requires an exchange calendar; this release adds no independent official calendar dataset.
- Internal gaps fail acceptance. Automatic incremental sync focuses on trailing updates and missing early history; force backfill for affected internal ranges.
- Quantile returns use available price pairs and remain sensitive to delisting and missing exits. They are not tradable long-short returns with all costs and constraints. The 70/30 holdout is a chronological diagnostic, not nested machine-learning validation.
- Financial visibility checks do not replace a provider's original historical revision archive.
- The Python editor bundle is large; Vite still warns about chunks above 600 kB. No Windows installer was built.
