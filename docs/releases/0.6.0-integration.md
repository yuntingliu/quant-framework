## 整合时修复的问题

1. 传统 RQ 同步结束检查会传入实际请求的股票、起止日期和因子字段；缺少整列 ROE 或只覆盖部分股票时不能标记完成。
2. 增量起点按每只股票自身的历史和上市日期计算，不再被其他股票的全表最新日期向前推移；过晚开始的历史会触发回补。
3. 日线覆盖检查使用本地可观察的交易日与上市区间组成的股票日期网格。内部缺口不能通过；只有明确的停牌状态能够解释缺少价格。同步行情和状态时，在状态全部落地后再次验收日线。
4. 因子分组在信号日确定。未来价格缺失只影响可计算的收益，不会把其他股票重新提升到高分组；整个分组缺少退出价格时，收益保持不可用。
5. 缺少输入时点审计时返回未验证，不再默认报告通过。
6. 研究验证统一使用 `context.diagnostics` 的副本，合并重复的 `research_quality` 定义和校验器，避免函数覆盖或循环依赖。
7. 当前数据缺失时，仍能打开验证代码与冻结回测；新回测保留数据检查。修复项目切换期间的结果隔离、深色参数输入框和子路径下的图标加载。
8. facade 检查明确导入当前工作区，避免另一份 editable install 掩盖本地接口缺失。

## 质量判定

`passed` / `status` 是项目所选质量门槛的结论；`evidence_status` 是信号证据诊断，可为 `pass`、`fail` 或 `insufficient`。默认保留原项目对实际成交与数据可靠性的要求，信号证据用于解释。可在 `validation.py` 中开启 `require_signal_evidence=True`，将证据不足或不达标纳入质量失败原因。任何“通过”都不表示保证收益。

旧项目的自定义验证代码保留原样。需要采用新默认验证模板时，在验证工作台使用“迁移官方模板”；该操作新建版本，历史回测保留当时的代码与输出。

## 使用

在本版本根目录、已有 Python 依赖的环境中，使用 `python -m` 启动，确保加载这份代码。交付压缩包包含前端构建：

```powershell
python -m uvicorn dashboard.backend.main:app --host 127.0.0.1 --port 8216
```

然后打开 `http://127.0.0.1:8216/app/`。依赖未安装时，先按 README 安装 Python 依赖。源码克隆需要运行 `npm --prefix dashboard/frontend ci` 和 `npm --prefix dashboard/frontend run build`。

真实研究通过未跟踪的 `.env` 配置 RQ，并在数据工作台选择请求范围、检查计划、同步及验收。交付包使用仓库原有演示样本，不包含本次测试产生的数据库修改、个人凭据或完整本地缓存。不要用演示样本代表无偏全市场股票池。

## 已知边界

- 交易日网格来自本地已有行情与市场状态。若某日从所有本地表中同时消失，仍需交易所日历发现；本版没有建立独立的官方日历数据集。
- 已有内部缺口会被拒绝验收。自动增量主要处理尾部更新和历史起点缺失；内部缺口可对受影响范围执行强制回补。
- 分组收益采用可用价格配对，仍可能受退市和缺少退出价格影响；它不是包含全部成本与交易限制的可交易多空净值。70/30 留出是时序诊断，不是嵌套调参后的机器学习样本外证明。
- 财务可用日期检查不能替代供应商原始历史修订版本档案。
- Python 编辑器构建包较大，Vite 仍提示部分 chunk 超过 600 kB；未制作 Windows 安装器。

本次只交付本地版本，没有推送远端。
